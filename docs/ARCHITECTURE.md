# Архитектура StreamBox

## Фактическое состояние

Репозиторий состоит из двух верхнеуровневых компонентов:

```text
mobile  → реализован базовый React Native-проект
backend → создан каталог и README, программного кода пока нет
```

Интеграции между ними пока нет. API-контракт, авторизация, хранение данных и инфраструктура backend не определены.

## Целевая граница системы

```text
┌─────────────────────────────┐
│ Mobile                     │
│ UI, навигация, локальное   │
│ состояние, платформенные   │
│ возможности                │
└──────────────┬──────────────┘
               │ HTTPS API
               │ контракт ещё не определён
┌──────────────▼──────────────┐
│ Backend                    │
│ бизнес-правила, данные,    │
│ авторизация, интеграции    │
└─────────────────────────────┘
```

Mobile не должен зависеть от внутренней реализации backend. Их границей станет версионируемый API-контракт. Секреты и привилегированные операции должны находиться на backend, поскольку данные внутри мобильного приложения нельзя считать секретными.

## Нерешённые системные вопросы

До начала полноценной интеграции необходимо определить:

- назначение продукта и основные пользовательские сценарии;
- формат и версионирование API;
- модель пользователей и авторизации;
- источник и модель медиаданных;
- правила загрузки, хранения и воспроизведения контента;
- окружения development, staging и production;
- мониторинг, аналитику, журналирование и обработку ошибок;
- CI/CD и способ развёртывания каждого компонента.

Эти пункты являются списком решений, а не описанием уже реализованных возможностей.
