# Участие в разработке

## Рабочий процесс

1. Создайте отдельную ветку от актуальной основной ветки.
2. Вносите небольшие логически связанные изменения.
3. Обновляйте тесты и документацию вместе с кодом.
4. Перед отправкой запустите проверки.
5. В pull request опишите цель, изменения и способ проверки.

Рекомендуемые имена веток: `feature/краткое-имя`, `fix/краткое-имя`, `docs/краткое-имя`.

## Проверки

```sh
cd mobile
npm run lint
npm test
npx tsc --noEmit
```

Команды выше относятся к мобильной части. После появления backend его обязательные проверки должны быть добавлены сюда и в `backend/README.md`.

Для нативных изменений соберите затронутую платформу. Для заметных UI-изменений приложите скриншоты или видео.

## Код и тесты

- Новые модули пишутся на TypeScript.
- Компоненты именуются в `PascalCase`, хуки начинаются с `use`.
- Сложная логика выносится из JSX в хуки, store или services.
- Сетевой код mobile размещается в `mobile/src/api`, платформенный — в `mobile/src/services`.
- Не отключайте правила линтера без пояснения причины.
- Тесты размещаются в `__tests__/` или рядом с модулем как `*.test.ts(x)`.
- В unit-тестах сетевые и платформенные зависимости подменяются.

Не коммитьте секреты, локальные настройки IDE, `node_modules`, Pods, сборочные артефакты и production-ключи подписи.
