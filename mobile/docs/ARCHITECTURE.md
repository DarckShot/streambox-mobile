# Архитектура мобильного приложения

`App.tsx` собирает SafeAreaProvider, QueryClientProvider и AuthProvider. `AppNavigation` управляет NavigationContainer и состояниями восстановления сессии, а `useAppInitialization` связывает состояние приложения с TanStack Query и загружает локальные настройки. React Navigation использует native stack и вкладки Home, Search, Favorites, Profile; deep links `streambox://` ведут на эти экраны, History, Settings, VideoDetails и Player.

Каталог, поиск и детали загружаются через `src/api/client.ts` и `src/api/videos.ts`. Base URL приходит из `.env` через нативный `react-native-config`; `apiConfig.ts` выбирает URL для iOS Simulator, Android Emulator или физического устройства. API client задаёт timeout и переводит сетевые ошибки, 404 и неверный ответ в типизированные ошибки. Компоненты не вызывают `fetch` и не обращаются напрямую к RUTUBE.

Для карточек API client преобразует исходный URL обложки в `/videos/:id/thumbnail`; изображение загружается через backend. При недоступной обложке карточка показывает заглушку.

`videoQueries.ts` содержит общие query keys и параметры кэша. Home запрашивает `/videos`, Search — `/videos?search=` после debounce, VideoDetails — `/videos/:id`, Player — `/videos/:id/playback`. Import и sync выполняются мутациями; они обновляют кэш видео и инвалидируют каталог. Повторное открытие экранов использует кэш с минутным stale time. При сетевой ошибке экран показывает повтор запроса. Временный playback URL имеет нулевой срок хранения в кэше и не записывается локально.

`AuthProvider` предоставляет контекст; восстановление сессии, вход и выход находятся в `useAuthSession`, перенос старых локальных данных — в `useLegacyMigration`. Refresh token хранится в нативном Keychain/Keystore, access token — в памяти. API client обновляет access token одним параллельным refresh-запросом и повторяет исходный запрос один раз. Если refresh невозможен, сессия закрывается. При logout Query cache очищается, а корневой navigator переключается на Login; приватный deep link ждёт успешного входа.

Favorites, History и progress идут через `api/me.ts` и TanStack Query с ключами, содержащими userId. Home строит «Продолжить просмотр» из серверного progress. История обновляется при начале воспроизведения, включая короткий просмотр до первого события прогресса. `useServerVideoProgress` отправляет позицию не чаще чем раз в 5 секунд, при seek и уходе с Player; временные ошибки сохранения повторяются, а отложенные запросы проверяют текущую сессию. Конец видео очищает запись. Fullscreen и custom controls остались в локальной логике плеера. Старые Async Storage данные читаются только миграцией перед открытием пользовательских экранов после входа и удаляются по одной записи после её успешного переноса; отсутствующие на backend видео пропускаются. При временной ошибке оставшиеся записи можно повторно перенести из Profile. Zustand хранит локальные настройки и не дублирует server state.

`useHistoryItems` объединяет историю, прогресс и актуальные видео; компоненты History отвечают за карточки и состояния экрана. Settings собирает отдельные секции воспроизведения и удаления данных; подтверждение удаления остаётся в UI, а операции выполняются через TanStack Query mutations.

Offline-слой: `networkState.ts` связывает NetInfo с TanStack `onlineManager`; `useAppInitialization` обновляет сеть и focus после foreground. `queryPersistence.ts` сохраняет только успешные запросы каталога, деталей и пользовательских коллекций/профиля в Async Storage, разделяя публичные и персональные записи по userId; TTL семь дней. Playback URL не сохраняется. `cachedIdentity.ts` держит последнюю подтверждённую идентичность в Keychain/Keystore, поэтому при временной ошибке refresh можно показать кеш только этого аккаунта. Logout очищает приватный Query cache в памяти.

`offlineQueue.ts` хранит изменения Favorites, History и progress по userId в Async Storage. Повторные операции над одним видео объединяются, а актуальная операция остаётся в очереди, если ответ на старую пришёл позднее. Запросы отправляются после восстановления сети; ошибки сети и сервера оставляют их в очереди, терминальные ошибки логируются и удаляются. `useServerVideoProgress` записывает позицию локально примерно раз в секунду, синхронизирует не чаще чем раз в пять секунд и при выходе; завершение ставит позицию 0 с новой временной меткой. Отображаемые коллекции учитывают ожидающие изменения. Глобальный QueryClient повторяет только сеть/timeout и отдельные 5xx, максимум два раза. Для общего client state новый Zustand store не нужен: текущий Zustand остаётся для настроек и строки поиска.
