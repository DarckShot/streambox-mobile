# Архитектура backend

## Фактическое состояние

Backend пока не реализован. Каталог `backend/` содержит только README. Язык, фреймворк, база данных, API и инфраструктура не выбраны.

Этот документ не предписывает конкретный стек. Он фиксирует вопросы и границы, которые необходимо определить перед разработкой.

## Предполагаемая ответственность

Backend должен владеть операциями, которые нельзя безопасно или последовательно выполнять на клиенте:

- бизнес-правилами и проверкой входных данных;
- пользователями, сессиями и правами доступа;
- долговременным хранением и изменением серверных данных;
- секретами и приватными ключами;
- интеграциями с внешними сервисами;
- выдачей мобильному клиенту версионируемого API.

Конкретный список обязанностей зависит от продуктовых требований и пока не является реализованной функциональностью.

## Граница с mobile

Mobile и backend должны взаимодействовать через явно описанный API-контракт. Внутренние модели базы данных не должны становиться контрактом клиента напрямую. Изменения API должны учитывать обратную совместимость с уже опубликованными версиями мобильного приложения.

## Решения до старта разработки

- язык, фреймворк и поддерживаемые версии;
- REST, GraphQL или другой формат API;
- спецификация контракта и генерация клиентских типов;
- модель авторизации;
- база данных, миграции и резервное копирование;
- фоновые задачи и обработка медиа;
- конфигурация, секреты и окружения;
- журналирование, метрики, tracing и уведомления;
- unit, integration и end-to-end тесты;
- контейнеризация, CI/CD и стратегия развёртывания.

После выбора стека этот документ следует заменить описанием фактических компонентов, направления зависимостей и ключевых архитектурных решений.
